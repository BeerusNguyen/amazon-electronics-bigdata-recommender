# E4 Chia dữ liệu và giao thức đánh giá

E4 gồm **T16–T19**. Đây là bộ dữ liệu và giao thức dùng chung cho các bước gợi ý Top‑10 của nhóm.

## Chạy E4 trên máy khác

Mở terminal tại **thư mục gốc repo**. Chuẩn bị Python **3.10**, JDK **17** và file ratings-only `Electronics.csv` gốc. Đặt file vào `data/raw/Electronics.csv`, hoặc truyền đường dẫn của máy bạn bằng `--csv "đường dẫn đến Electronics.csv"`.

### Windows PowerShell

```powershell
py -3.10 -m venv .venv-e4
. .\.venv-e4\Scripts\Activate.ps1
java -version
python -m pip install "pyspark==3.5.3" "numpy==1.24.3" "pandas==2.0.3" "pyarrow==23.0.1" "pytest>=8,<9"

$env:SPARK_MASTER = 'local[2]'
$env:SPARK_DRIVER_MEMORY = '3g'
$env:SPARK_LOCAL_IP = '127.0.0.1'
$env:PYSPARK_PYTHON = 'python'

python -m src.splitting.run_e4 prepare --cohort-bps 500
if ($LASTEXITCODE -eq 0) { python -m src.splitting.run_e4 audit }
```

### Linux và macOS

```bash
python3.10 -m venv .venv-e4
source .venv-e4/bin/activate
java -version
python -m pip install "pyspark==3.5.3" "numpy==1.24.3" "pandas==2.0.3" "pyarrow==23.0.1" "pytest>=8,<9"

export SPARK_MASTER='local[2]'
export SPARK_DRIVER_MEMORY='3g'
export SPARK_LOCAL_IP='127.0.0.1'
export PYSPARK_PYTHON="$(command -v python)"

python -m src.splitting.run_e4 prepare --cohort-bps 500 &&
    python -m src.splitting.run_e4 audit
```

Nếu PowerShell chặn script kích hoạt venv, dùng Command Prompt chạy `.venv-e4\Scripts\activate.bat`, rồi đặt các biến Spark bằng `set TÊN_BIẾN=giá_trị` trước hai lệnh Python. Nếu `java -version` báo lỗi hoặc trỏ tới JDK khác, đặt `JAVA_HOME` tới JDK 17 và thêm thư mục `bin` của JDK đó vào `PATH`.

Các lệnh trên dùng môi trường PySpark của lượt E4 đã kiểm chứng trên Windows. Bước `prepare` dùng Spark để đọc và chia dữ liệu, rồi ghi Parquet qua Pandas/PyArrow. Bước `audit` đọc các tập đã ghi và tạo báo cáo cùng ID mapping. Hai bước dùng bộ nhớ driver để xử lý mẫu, vì vậy có thể chạy pilot khoảng **0,5% user** trước trên máy ít RAM.

```text
python -m src.splitting.run_e4 prepare --cohort-bps 50 --out data/subsets/e4-pilot
python -m src.splitting.run_e4 audit --out data/subsets/e4-pilot
python -m pytest -q tests/test_e4_audit.py src/etl/test_etl_pipeline.py
```

## Đầu ra bàn giao

Lượt chính lấy khoảng **5% user** với `--cohort-bps 500`. Cả hai lệnh mặc định dùng **`data/processed/e4/`**. `prepare` cần một thư mục đầu ra mới. Để chạy thêm một lượt, truyền cùng một đường dẫn `--out` cho cả `prepare` và `audit`, ví dụ `--out outputs/e4-new`.

```text
data/processed/e4/
├── train.parquet
├── validation.parquet
├── test.parquet
├── split_manifest.json
├── split_statistics.csv
└── audit/
    ├── cold_start.csv
    ├── snapshot_manifest.json
    ├── validation/
    │   ├── user_id_map.parquet
    │   └── item_id_map.parquet
    └── test/
        ├── user_id_map.parquet
        └── item_id_map.parquet
```

Ba file Parquet ở cấp trên là dữ liệu rating đã chia. `split_statistics.csv` ghi số dòng và khoảng thời gian. `split_manifest.json` ghi SHA-256 của CSV, seed, mốc chia và số dòng bị loại. Trong `audit/`, `cold_start.csv` ghi số liệu theo nhóm và `snapshot_manifest.json` ghi lịch sử của từng kỳ. Dùng bộ ID mapping tương ứng với Validation hoặc Test.

Bản bàn giao **1.031.437 cặp user–item** có sẵn trong [data/processed/e4/](../data/processed/e4/) sau khi clone hoặc pull nhánh `main`. Để tự chạy lại, dùng `--out` với một thư mục mới như trong hướng dẫn trên.

## T16 Chia Train Validation Test theo thời gian

Pipeline đọc `Electronics.csv` gốc, chuẩn hóa ID, kiểm tra điểm nguyên 1–5, bỏ bản sao hoàn toàn và giữ lượt đánh giá **sớm nhất** của từng cặp user–item. Cặp có các điểm khác nhau tại cùng timestamp sớm nhất được loại và ghi vào báo cáo. E4 dùng CSV gốc vì bảng ratings sạch của E3 giữ lượt đánh giá mới nhất.

E3 có chế độ `--pair-policy history` để giữ các lượt đánh giá khác nhau sau khi bỏ bản sao hoàn toàn. Bảng `ratings_clean` của E3 dùng chính sách `latest` để biểu diễn trạng thái gần nhất. E4 áp dụng `earliest` trên CSV gốc để xác định thời điểm cặp user–item xuất hiện lần đầu. [Chế độ làm sạch của E3](E3_README.md)

Pilot lấy khoảng **0,5% user** và lượt chính lấy khoảng **5% user** bằng Spark hash với seed 42. Pipeline giữ toàn bộ lịch sử của mỗi user được chọn trước khi bỏ trùng.

| Tập | Khoảng thời gian UTC | Pilot | Lượt chính |
| --- | --- | ---: | ---: |
| Train | Trước 2017-02-01 | 81.430 | 819.984 |
| Validation | Từ 2017-02-01 đến trước 2017-10-01 | 10.628 | 106.147 |
| Test | Từ 2017-10-01 đến hết kỳ | 10.275 | 105.306 |
| **Tổng số cặp** | | **102.333** | **1.031.437** |

Mỗi cặp user–item chỉ xuất hiện một lần trên toàn bộ ba tập. Mã kiểm tra ba tập đều có dữ liệu, thời gian không chồng lấn và tổng số dòng khớp báo cáo làm sạch. [Thống kê chia tập của lượt tham chiếu](../src/splitting/results/main/split_statistics.csv)

## T17 Audit cold-start

Validation kiểm tra sự xuất hiện của user và item trong **Train**. Test dùng lịch sử **Train + Validation**. Mỗi giai đoạn giữ lịch sử cố định kể từ đầu kỳ. Báo cáo có bốn nhóm warm/cold và ba nhóm số tương tác lịch sử của user là **0, 1–4, từ 5**. Một user có thể có nhiều dòng thuộc các nhóm warm/cold khác nhau.

| Nhóm | Cặp trong Test lượt chính |
| --- | ---: |
| Warm user – warm item | 40.458 |
| Cold user – warm item | 49.476 |
| Warm user – cold item | 6.925 |
| Cold user – cold item | 8.447 |
| **Tổng** | **105.306** |

Tỷ lệ của từng nhóm lấy tổng số cặp của kỳ làm mẫu số. Manifest cũng ghi tỷ lệ ID chưa biết theo số user hoặc item duy nhất của kỳ. [Báo cáo cold-start](../src/splitting/results/main/audit/cold_start.csv) · [Manifest snapshot](../src/splitting/results/main/audit/snapshot_manifest.json)

## T18 Giao thức đánh giá Top‑10

- Dùng chung bộ chia thời gian, mẫu user, lịch sử snapshot và catalog ứng viên khi so sánh các phương pháp.
- Sản phẩm relevant có rating **≥ 4** trong kỳ đánh giá. Loại item user đã đánh giá trong lịch sử khỏi danh sách gợi ý. Catalog ứng viên của snapshot gồm sản phẩm đã xuất hiện trong lịch sử đó.
- Điểm warm user–warm item chỉ xét các mục tiêu warm của user warm. Báo cáo toàn bộ user giữ cả mục tiêu cold-item trong mẫu số để phản ánh giới hạn của catalog. Trình bày riêng bốn nhóm cold-start và các mức lịch sử user.
- Tính trung bình Recall@10 và NDCG@10 trên user có ít nhất một mục tiêu relevant trong nhóm. Coverage tính trên toàn bộ user được đánh giá, gồm tỷ lệ nhận ít nhất một gợi ý và tỷ lệ nhận đủ 10 gợi ý. Danh sách dưới 10 được tính theo đúng số vị trí trả về.
- Chọn cấu hình trên Validation. Sau khi chốt, dùng Train + Validation làm lịch sử cho đánh giá Test.

Ví dụ, nếu tập relevant là `{A, C}` và danh sách là `[X, A, B]`, Recall@10 bằng `1/2`. DCG nhị phân bằng `1/log2(3)`, IDCG bằng `1 + 1/log2(3)`, nên NDCG@10 xấp xỉ **0,3869**.

## T19 Ánh xạ ID

Mỗi snapshot tạo hai bảng ánh xạ từ các ID duy nhất trong lịch sử, sắp theo ID gốc và gán số nguyên 32 bit từ 0. Giữ cả hai cột để ánh xạ ngược. ID chỉ xuất hiện trong kỳ đánh giá được ghi nhận là unknown trong audit. Mapping Test được tạo lại từ Train + Validation.

- **Validation lượt chính:** 401.457 user, 190.150 item.
- **Test lượt chính:** 446.391 user, 203.850 item.

Các bảng `user_id_map.parquet` và `item_id_map.parquet` được lưu dưới `audit/validation/` và `audit/test/`.
